# 搜狗词库清理工具（sogou-dict-cleaner）

清理搜狗输入法用户词库里的乱码词条，也可以把词库导出成文本、编辑后再写回能被搜狗「恢复」的备份文件。

搜狗用久了，用户词库里会混进一些乱码词，比如「㥒쮤」「⍤Ⰻ⁅」，打字时偶尔会冒出来，在输入法里又没法批量删除。这个工具直接处理搜狗导出的备份文件（`.bin`）：删掉乱码，再恢复回去。

只用 Python 3 标准库，不需要安装依赖。

## 快速开始

1. 在搜狗输入法「偏好设置 › 词库 › 中文用户词库」里点「导出/备份」，得到一个 `.bin` 文件。
2. 清理：

   ```bash
   python3 sogou_dict.py clean 搜狗词库备份.bin 清理后.bin
   ```

3. 回到搜狗，用「恢复（完全覆盖）」选择 `清理后.bin`。

**原始备份请留好。** 恢复会完全覆盖当前词库，有问题时用原始备份再恢复一次即可。

## 命令

| 命令 | 作用 |
|---|---|
| `export 备份.bin [输出.txt]` | 导出为文本，每行 `词<Tab>拼音<Tab>词频`，拼音之间用空格分隔 |
| `clean 备份.bin 输出.bin` | 一步删除乱码词条，直接生成可以恢复的 `.bin` |
| `rebuild 备份.bin 编辑后.txt 输出.bin` | 按编辑后的文本重建 `.bin`，可以删词、改词频、加词 |
| `check 文件.bin` | 按搜狗加载时的逻辑检查文件头 |

想手动挑着删词，可以先 `export` 出文本，用编辑器删掉不要的行，再 `rebuild`。

### 什么算乱码

`clean` 会保留只由以下字符组成的词：

- 汉字（含扩展区）
- 可见的 ASCII 字符（字母、数字、常见符号，所以 `k8s`、`MD5`、`CO2` 这类词会保留）
- 「〇」

此外，备份里有一些记录的文字部分根本无法解码（像是删除后留下的残留），这些也会一并删掉。

**清不掉的情况：** 全部由生僻汉字组成的乱码（例如「稚憎衙」，拼音却是 zi jia wan），单看字符判断不出来，需要对照拼音才能识别，目前还没有处理。

## 恢复失败？先检查文件权限

如果搜狗提示「恢复（完全覆盖）中文用户词库失败！」，但文件本身没问题，多半是 **macOS 的隐私保护**造成的：

- 「文稿」「桌面」「下载」三个文件夹受隐私保护（TCC）。
- 搜狗导出的备份文件带有授权，输入法进程能读取。工具新生成的文件没有这个授权，在恢复对话框里选中文件时，系统只授权给了偏好设置程序，真正读文件的输入法进程读不到，于是直接报失败，连日志都不写。

解决办法（任选其一）：

- 把生成的 `.bin` 放到主目录下不受保护的文件夹里（例如 `~/搜狗词库/`），再去恢复。
- 在「系统设置 › 隐私与安全性 › 文件和文件夹」里给搜狗输入法开启「文稿」等文件夹的权限。

## 原理

`rebuild` 和 `clean` 都**以原始备份为模板**，而不是从零生成文件：

- 保留的词条从原文件逐字节复制，词条里含义还不清楚的字段（例如「最近使用」序号）也原样保留。
- 文件头只改 4 个字段：条数、已用大小、零词频条数、校验和。文件头里那几个含义未知的统计值保持原值。
- 写出前会按搜狗的校验逻辑（`t_dictBase::CheckValid`）自检一遍。
- 一条都不删时，输出和原文件逐字节完全相同。

新增词条按备份里常见的词条格式构造，**属于实验性功能**，还没有在搜狗里实际验证过。另外，新增后的词条总数不能超过原文件的容量。

### 文件格式（SGPU）

| 偏移 | 含义 |
|---|---|
| `0x00` | 魔数 `SGPU` |
| `0x10` | 文件总长度 |
| `0x20` | 校验和：文件头各字段之和，不含它自己和 `0x28–0x37` |
| `0x28` | 最大的「最近使用」序号（`0x2C–0x34` 是搜狗的统计值，不参与校验） |
| `0x38` | 索引起点、索引容量、条数、数据区起点、数据区容量、已用大小（6 个 uint32） |
| `0x54` | 词频为 0 的条数 |

索引是一组指向数据区的 uint32 偏移。每个词条的格式为：

```
词频 u16 | 序号 u16 | 5 字节标记 | 拼音字节数 u16 | 拼音码 u16×n | 扩展长度 u16 | 词字节数 u16 | 词(UTF-16LE) | 尾部(通常是拼音副本)
```
